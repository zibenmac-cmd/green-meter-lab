## ADC 与 V、A、W 的区别

ADC 是设备传来的原始采样计数。当前显示两路原始 RMS，**不能把 119.4 ADC 理解成 119.4 V，也不能把 17.9 ADC 理解成 17.9 A**。当前波形包含零点偏置，软件不会自动减去平均值来伪装完成标定。

新版实测模式在未确认标定时不计算物理功率、功率因数、谐波和电量，不生成瓦数摘要，也不推送 n8n。建议先核对空载零点，再对照参考仪表核对通道、比例、极性及采样率。面板保留的 6400 Hz 和旧程序的 1.935205 / 0.011848 系数均未因这次收数而得到验证。

确认换算、零点、实际采样率及负载阈值后，才勾选对应确认框，再连接设备；此时软件使用 v=(ADCv-零点)×系数、i=(ADCi-零点)×系数×极性计算。软件积分只涵盖收到的完整帧，不补算缺失片段，不等于全时段累计用电。

## 数据文件

- **保存波形 CSV**：导出最近一帧；ADC 模式列名为 current_adc,voltage_adc,label，已标定/物理文件模式为 I,V,label。
- **导入波形 CSV**：接受物理单位的 I,V,label 或 Voltage,Current；原始 ADC 文件请用 BIN 回放。
- **导出原始 BIN**：保留接收字节，供后续复核。原始数据可能包含设备配置回复，分享前检查。
- **导出真实摘要**：标定确认后的连续采集按秒生成；只保存在内存，退出前导出。
- **导出诊断 JSON**：明确区分 raw_metrics 与物理 metrics，保留帧数、丢弃字节与来源。
- **保存/加载配置**：配置不自动传给硬件。n8n 默认关闭，只有明确开启后的真实物理摘要才发送；文件回放不发送。

应用包含本次抓包副本 Evidence/F251D351-实测原始.bin、SHA256 与解析清单，不会改动独立测试器保存的原文件。此应用运行于本机，当前未自动同步至云端网站。

## 开发与兼容

Source/ 为新 Mac 源码；Tests/main.swift 为回归检查，Evidence/ 为本次真实抓包。运行 zsh build.sh 生成 .app；编译目标为 macOS 13+ 的 arm64 与 x86_64。当前 Mac 已实际启动验证 arm64，Intel 与旧 macOS 仅完成编译目标设置。
