# 绿电实验室 YS8000 接入与模型使用

本版已提供波形分析、可训练的 KNN 电器候选识别、30 秒功率预测和采集网关。设备尚未到位，网络地址、二进制帧格式、校准系数和实测识别效果均需联调。网页中的资料样例来自用户提供的 KNN4XM 压缩包，不是本项目新采集的数据。

## 数据怎样进入网页

YS8000 在局域网发送电压/电流采样 → 同一网络中的 Windows/macOS/Linux 电脑运行 Python 网关 → 私有 HTTPS 接口 `/api/ys8000` → 用电记录与最新波形 → 波形分析、候选识别和短时预测。

目标为每秒 6400 对电压/电流采样。在 50 Hz 电网下，每周波 128 对采样，对应旧代码布局下每帧 518 字节。此处的 6400 指采样点数，不表示每秒做 6400 次电器分类。请向设备提供方确认“6400 点”是每通道采样率还是两通道合计，以及实际通道顺序。

网关每秒计算一次有功功率，每 10 秒上传一个功率均值、软件积分电量、最新 3 个周波（384 对点）以及最近最多 180 秒的功率摘要。网页每 10 秒刷新，超过 60 秒未更新显示数据中断。高频原始波形不全量保存到云数据库，最新波形快照会被后续快照替换；10 秒用电摘要会保留。

## 收到设备后确认这些参数

1. 手册默认 IP 为 `192.168.1.2`，端口 `8266`，热点模式、服务器角色。旧代码使用 `192.168.1.1`。先用设备的 `ifconfig` 命令核对。
2. 按手册一次发送一条小写命令。`#` 开始发送数据，`$` 停止发送数据。NetAssist.exe 可在 Windows 上用于 TCP 调试；Mac 无法直接运行该 exe，本网关使用跨平台 Python，无需依赖它。
3. 手册没有描述完整二进制帧。旧代码截取前 3 字节和后 3 字节，将中间数据按 int16 解析，前半部分为电压、后半部分为电流。其帧尾检查代码存在错误，不能据此推断完整帧尾。必须抓到完整报文，再填写 `header_hex`、`trailer_hex` 和 `byte_order`。本网关严格要求 3 字节帧头、3 字节帧尾；如实物布局不同，需修改解析器。
4. 旧代码的系数为电压 `1.935205`、电流 `0.011848`，属于待验证的参考值。用参考电表与已知负载核对零点、有效值、有功功率和电流方向。`current_sign` 只能在确认极性后设置为 `1` 或 `-1`，不能为了让数值变正而随意反转。
5. 旧样例采样率是 1600 Hz，研究演示稿描述了 3000 Hz。本次目标是 6400 Hz，不能把相同文件随意改成另一采样率解释。

## 启动采集程序

需要 Python 3.9 或更新版本，无额外 Python 包依赖。下载 `ys8000_gateway.py` 和 `ys8000-config.json`，放到同一文件夹。

填写配置模板中的地址、采样数、帧标记、字节序、零点和标定系数。完成实际核对后，才将 `frame_format_confirmed` 和 `calibration_confirmed` 设为 `true`。模板默认拒绝连接，以免未知报文被误当作有效测量。

先检查配置（不连接设备或网站）：

```sh
python3 ys8000_gateway.py --config ys8000-config.json --check-config
```

在网页“设备配置”中生成采集密钥。私有站点另需平台提供的服务访问凭据，凭据仅交给采集电脑，放在环境变量中，不要写入配置 JSON、源码、聊天或截图。

macOS/Linux（示例占位值须替换）：

```sh
export METER_SITE_URL="https://green-meter-lab-ahaoxiao.ziben-mac.chatgpt.site"
export METER_INGEST_KEY="替换为采集密钥"
export METER_SITE_ACCESS_TOKEN="替换为平台服务访问凭据"
python3 ys8000_gateway.py --config ys8000-config.json --state ys8000-state.sqlite
```

Windows PowerShell 使用 `$env:METER_SITE_URL`、`$env:METER_INGEST_KEY` 和 `$env:METER_SITE_ACCESS_TOKEN` 设置相同变量，启动命令使用 `py -3 ys8000_gateway.py --config ys8000-config.json --state ys8000-state.sqlite`。

本机预览时 `METER_SITE_URL` 可为 `http://127.0.0.1:5173`，不需要平台服务访问凭据，仍需本机网页生成的采集密钥。线上 Cloudflare 拦截属于平台访问问题，网关不会绕过访问限制。

## 电量与断连处理

- 有功功率 `P = mean(v × i)`，单位 W。电压/电流有效值取均方根，视在功率 `S = Vrms × Irms`，功率因数 `PF = P/S`。
- 能量根据完整采集片段的有功功率积分：`kWh = P × 秒数 / 3,600,000`。这不是硬件累计电量寄存器读数，网页会标为“YS8000 积分估算”。
- 负有功功率不会取绝对值。网关停止并提示检查接线和标定，离线分析保留负值并显示提示。
- 接收中断或帧失配后丢弃未完成采集窗口，不补算缺失时间。没有序列号/校验码的现有资料不能保证检测所有丢帧或位错误，正式测量需核实完整协议。
- 能量计数和待上传队列保存在本机 SQLite 文件。上传失败会重试，已发送的数据由设备号与时间戳去重；401/403 等配置错误会暂停采集并保留队列。
- 重启保持同一状态文件可继续计数。标定或采样配置改变时需要新状态文件，会产生新会话和计数重置，网页按会话隔开计数，不把跨会话差值或重置当作节电。
- SQLite 不保存访问密钥。请保留该文件；积压过多时会占用本机磁盘。停止程序后再次启动会先继续处理队列。网关只发送采集开始/停止命令，不控制继电器。

## 使用波形分析与 KNN 候选识别

1. 进入“波形实验”。“资料样例”分析历史参考文件；“导入 CSV”分析本机 `I,V,label` 文件；“设备实时”显示接口快照。历史文件不会写入用电统计。
2. 波形单位必须已换算为 A 与 V。设置真实采样率和电网频率，采样数需为完整周波的整数倍。
3. 在 KNN 区域给电器或负载组合命名，再加入多次独立采集文件。每类至少 2 个片段，至少 2 类。训练与待识别波形必须使用相同采样配置。改变采样参数会清除当前页面的样本与模型。
4. 模型使用最后 3 个周波的 13 个特征：电压/电流有效值、有功功率、功率因数、电流直流占比、偏度、峰度、2/3/5/7/9/11 次谐波相对电流有效值。标准化后使用 3 邻居投票，并按类内特征距离给出拒识阈值。
5. 投票占比不是校准后的概率。超出学习范围或平票时显示未知/不确定。只有已学习的电器、档位或组合才可能被正确识别；不等同于已经实现任意多电器的 NILM 分解。
6. 训练和模型导入在本机浏览器完成，不上传标注文件。模型仅在当前页面保留，离开/刷新前使用“导出模型”，下次导入 JSON。不要导入不可信的 pickle 或运行原压缩包中的 Python 模型加载代码。
7. 模型是否可用于比赛，应使用独立采集的测试集，按电器类别统计混淆矩阵、准确率、召回率与未知负载表现。当前页面不自动宣称模型准确率。

## 波峰波谷预测

设备实时页至少需要 90 秒连续的每秒有功功率摘要。也可以导入 timestamp,power_w 格式的历史每秒功率 CSV，在本机预测该序列末尾之后的 30 秒；页面和导出报告会标明历史来源，不会把它当作当前实时预测。模型使用最多最近 180 秒，训练带正则化的 AR(6) 自回归模型，递归预测未来 30 秒，标出预测最高点与最低点。

最近 20 秒作为时间顺序保留段做一步预测，页面显示 MAE；未来的阴影按残差 RMSE 与预测步长扩展，仅为经验误差范围。该回测不能证明 30 秒预测准确性，正式验证应额外保存预测与之后的实测值进行对比。

断连、采样缺口、样本不足、外推不稳定时暂停预测。接近恒定的负载会显示“暂未形成清晰峰谷”。预测不能提前知道尚未发生的电器开关动作，不用于自动断电。

## 与研究演示稿的关系

Christian Ekpo Nelson 的 2026 年 5 月演示稿研究烘干机模式分类与剩余运行时间，输入为 20 分钟 × 22 特征，使用条件多任务 BiTCN。提供的文件没有 BiTCN 权重、特征流水线、标签映射和完整训练数据。本次实现的 KNN 与 AR 模型是可运行的第一版，不是对其模型的复现。原研究准确率、误差和数据规模不作为本项目成果。
